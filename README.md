# Автоподнятие тем LOLZTEAM

Python 3.11–3.13, macOS или Linux. Установка:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

В существующем `.env` оставьте свой токен и добавьте реальные ID тем:

```dotenv
LZT_TOKEN=ваш_токен
LZT_THREAD_IDS=1234567,2345678,3456789
```

Токену требуется право `post`: https://lolzteam.readme.io/reference/threadsbump

Запуск: `python main.py`. При первом запуске скрипт сразу пытается поднять
каждую тему. Следующая попытка после успеха — через 36 часов и 5 секунд.
Успех определяется по HTTP 200 и JSON без `errors`, `error` или `success=false`.
Это подтверждение API; место темы в списке отдельно не проверяется.

При ошибке КД скрипт извлекает остаток времени из сообщения API в `errors`:
«Вы должны подождать 13 часов 21 минута 30 секунд, чтобы поднять эту тему».
Поддерживаются дни, часы, минуты, секунды и их склонения, HTML и пропущенные
единицы. Повтор назначается через указанный остаток + 5 секунд запаса.
КД не считается сбоем: счётчик неудач сбрасывается, расписание сохраняется в БД.
После успеха скрипт снова ждёт 36 часов и 5 секунд.

При остальных ошибках (включая нераспознанный формат КД) повторы:
5, 10, 20, 40, 60 минут, далее раз в час.
Заголовок `Retry-After` может увеличить ожидание.
Отказы из-за токена, прав или удалённой темы тоже видны в логах;
автоматические повторы сами такие проблемы не устраняют.

Расписание, время последнего успеха и последний статус находятся в
`state.sqlite3` рядом со скриптом. Не удаляйте файл, чтобы сохранялось расписание.
После простоя просроченные темы обрабатываются по одному разу, без догоняющей серии.
Если процесс оборвался во время запроса, его результат может быть неизвестен:
после запуска возможна повторная попытка. Гарантия «ровно один запрос» отсутствует.

Логи Loguru: консоль и `logs/autoup.log`, ротация по 10 MB, хранение 14 дней.
Вторая копия в этой же папке не запустится благодаря блокировке `autoup.lock`.
Копии в других папках имеют отдельные блокировки и расписания.

Запрос имеет таймаут 60 секунд; суммарное ожидание одной темы с внутренними
повторами SDK ограничено 120 секундами. Между темами — 10 секунд.
Остановка: Ctrl+C или SIGTERM. Уже записанное расписание сохраняется.
Ошибки конфигурации/БД завершают процесс с ненулевым кодом.

Для работы после закрытия терминала и перезагрузки настройте системную службу
(`systemd` на Linux или `launchd` на macOS) с перезапуском при сбое.
Сам скрипт службу не устанавливает. Во время сна/выключения компьютера запросы
не выполняются. На Windows блокировка через `fcntl` не поддерживается.

Проверки без сети: `python -m unittest -v`.
